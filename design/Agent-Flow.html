agent 拿着 Key 对真实接口验证到通过，再把配置放进剪贴板

检查循环发生在 agent 一侧。在设置页选择「新增服务」或修改指定服务，再粘贴配置。新增服务保存后需手动选用。

> [粘贴“复制给 agent 的说明”的内容] 我用 DeepSeek，Key 在 ~/.secrets/deepseek
读取 docs/agent-setup.md … KEY=$(cat ~/.secrets/deepseek)，不打印
curl api.deepseek.com/chat/completions model=deepseek-flash body.thinking.type=disabled → 成功
jq -n --arg k "$KEY" '{ type: "deepseek", apiKey: $k, model: "deepseek-flash", … }' | pbcopy
已验证并复制到剪贴板。打开简道翻译设置页，在“翻译服务”里点“修改”（未配置时输入框已经在那里），粘贴，点“应用”。
1 · 用户
复制说明交给 agent
设置页“翻译服务”未配置时直接可见，已配置时点“修改”后可见。说明里是指南链接和当前服务配置（Key 已脱敏）。
2 · agent
问清服务，用 Key 验证到通过
问用哪家、Key 在哪。按指南里的请求模板发请求，被拒就换模型或去掉 body 字段再试。
3 · agent
配置进剪贴板
只含翻译服务本身的字段。用 jq 生成 JSON 写入剪贴板，Key 不出现在 agent 的输出里。不走 URL，因为浏览器历史会记下完整地址。
4 · 用户 · 简道翻译
在设置页原地粘贴，应用
编辑框在“翻译服务”一节里原地出现，不开弹窗。贴入后显示“应用后”的预览；应用时先测连接，通过才保存配置和检查结果并清空剪贴板，然后收回成预览。
之后要换模型或参数：点“修改”，编辑框里是当前服务配置（Key 只剩前缀和末四位），可以直接改字段；也可以复制说明交给 agent，把它带回的配置贴进来。脱敏的 Key 原样保留时，简道翻译沿用已存的 Key。
{ "type": "deepseek", "apiKey": "sk-…a9f2", "model": "deepseek-flash", "body": { "thinking": { "type": "disabled" } } }
type：openai · anthropic · gemini · deepseek · openai-compatible（需 baseURL）。可选：api（openai-responses · openai-chat · anthropic · gemini）、name、baseURL、headers、body、temperature。语言、显示方式和提示词不在这份配置里。
所以只有首次配置和换 Key 时，剪贴板里才会出现明文 Key。
