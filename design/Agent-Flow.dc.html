agent 拿着 Key 对真实接口验证到通过，再把配置放进剪贴板

检查循环发生在 agent 一侧。简道翻译只收一份已验证的配置，不需要回传结果的通道。

> [粘贴“复制给 agent 的说明”的内容] 我用 DeepSeek，Key 在 ~/.secrets/deepseek
读取 docs/agent-setup.md … KEY=$(cat ~/.secrets/deepseek)，不打印
curl api.deepseek.com/chat/completions model=deepseek-flash body.thinking.type=disabled → 成功
jq -n --arg k "$KEY" '{ jiandao: 1, provider: { … } }' | pbcopy
已验证并复制到剪贴板。打开简道翻译弹窗，粘贴，点“应用并翻译此页”。
1 · 用户
复制说明交给 agent
弹窗和设置页都有“复制给 agent 的说明”。说明里是指南链接和当前配置（Key 已脱敏）。
2 · agent
问清需求，用 Key 验证到通过
问用哪家、Key 在哪、读什么语言。按指南里的请求模板发请求，被拒就换模型或去掉 body 字段再试。
3 · agent
配置进剪贴板
用 jq 生成 JSON 写入剪贴板，Key 不出现在 agent 的输出里。不走 URL，因为浏览器历史会记下完整地址。
4 · 用户 · 简道翻译
粘贴，看预览，应用
预览一行：服务 · 模型 · 主机。弹窗里应用后直接翻译此页；设置页里应用后发一条短请求确认连接。两处都会清空剪贴板。
之后要换服务、模型或参数：再点一次“复制给 agent 的说明”。说明末尾附当前配置，Key 只剩前缀和末四位；agent 原样带回，简道翻译沿用已存的 Key。
{ "jiandao": 1, "provider": { "type": "deepseek", "name": "DeepSeek", "apiKey": "sk-…a9f2", "model": "deepseek-flash", "body": { "thinking": { "type": "disabled" } } }, "targetLanguage": "cmn", "sourceLanguage": "auto", "mode": "bilingual" }
provider.type：openai · anthropic · gemini · deepseek · openai-compatible（需 baseURL）。可选 api：openai-responses · openai-chat · anthropic · gemini。可选 prompt：自定义提示词，null 恢复默认。
所以只有首次配置和换 Key 时，剪贴板里才会出现明文 Key。
